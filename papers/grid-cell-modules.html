1The big idea in one paragraph

In the entorhinal cortex, grid cells fire at a repeating triangular lattice of locations as an animal moves. A grid cell module is a population of grid cells that share one lattice scale and orientation; what differs between them is the relative position at which each fires. Sort the cells by that relative position and a module collapses into a small rhombus-shaped tile with a single bump of activity. Because the lattice repeats, one module cannot say where you are — the same bump recurs all over the environment. But the paper's central move is this: stack several modules with different scales and orientations, and the combination of their bumps almost never repeats. A few small, ambiguous codes multiply into one large, sparse, essentially unique code for location — and movement updates it through path integration. This page lets you build that code by hand.

Key idea

Each module is a low-resolution, wrap-around ruler. No single ruler is enough. Read several rulers of different scale and tilt at once and only one location in the whole environment is consistent with all of them — like reading a vernier scale, or the hands of a clock.

What the numbers mean

Per module you control: scale \(s_i\) (lattice spacing in the arena — bigger = coarser ruler), orientation \(\theta_i\), cells \(w\) (the SDR has \(w^2\) bits), and readout \(\delta\varphi\) (smaller = sharper, sparser bump). "Distinguishable phases" is \(\approx(1/\delta\varphi)^2\) — the number of locations one module can resolve before it repeats. The combined capacity multiplies across modules, which is why a few small modules represent so much.

5The math, in one screen

Everything the demo just did reduces to a handful of equations. A module's whole state is a 2-D phase \(\vec{\varphi}\in[0,1)\times[0,1)\) — where the bump sits in the rhombus.

Movement → a shift in phase (path integration)

Each module owns a 2×2 matrix \(M_i\) built from its scale \(s_i\) and orientation \(\theta_i\). It turns a movement of the sensor in the world into a movement of the bump, baking in the 60° lattice geometry:

Eq. (3) — the module's scale/orientation transform
$$ M_i = \begin{bmatrix} s_i\cos\theta_i & s_i\cos(\theta_i+60^\circ)\\[2pt] s_i\sin\theta_i & s_i\sin(\theta_i+60^\circ)\end{bmatrix}^{-1} $$
Eq. (4) — every movement \(\vec{d}_t\) shifts the bump, wrapping with mod 1
$$ \vec{\varphi}^{\,i}_{t,\text{move}} = \left(\vec{\varphi}^{\,i}_{t-1,\text{sense}} + M_i\,\vec{d}_t\right)\bmod 1 $$
Why the demo can jump anywhere instantly

Applying Eq. (4) step after step just sums the displacements, so the bump's phase has a tidy closed form: \(\vec{\varphi}^{\,i}(\vec{x}) = \big(\vec{\varphi}^{\,i}_0 + M_i(\vec{x}-\vec{x}_0)\big)\bmod 1\). The demo computes phase straight from the sensor's position. A neat consequence: the code at a place is independent of the path you took to get there — wander off and come back and the SDR is identical.

Phase → which cells are on (the Gaussian bump)

Each cell \(c\) sits at a fixed phase \(\vec{\varphi}_c\) (the module is partitioned into \(w\times w\) equal tiles). A cell's scalar activation is a Gaussian of its distance to the bump \(b\), measured on the rhombus (so it wraps around the edges):

Eqs. (10–11) — Gaussian activation
$$ \text{Gaussian}(d) = e^{-d^2/2\sigma^2}, \qquad a_{c,b} = \text{Gaussian}\!\big(\text{Distance}(\vec{\varphi}_c,\vec{\varphi}_b)\big) $$

A cell is part of the SDR when its activation clears a threshold set by the readout resolution \(\delta\varphi\) — roughly the diameter of phases one bump should stand for:

Eqs. (13–14) — threshold into a binary SDR
$$ A^{\text{loc},i,c}_{t}=\begin{cases}1 & a_c \ge a_{\text{active}}\\ 0 & \text{otherwise}\end{cases}, \qquad a_{\text{active}} = \text{Gaussian}\!\left(\tfrac{\delta\varphi\cdot 2}{2\sqrt{3}}\right) $$
A subtlety worth knowing

With a single bump, \(\sigma\) drops out of which cells turn on: the threshold is just "distance \(\le \delta\varphi/\sqrt3\)", so \(\delta\varphi\) alone controls sparsity. \(\sigma\) only shapes the colourful gradient you see, and starts to matter once a module holds a union of several bumps (Eq. 12, \(a_c = 1-\prod_b(1-a_{c,b})\)). This demo shows one bump per module, as you asked — but the same machinery represents uncertainty as a union. The paper's baselines are \(\sigma=0.18172\), \(\delta\varphi=\tfrac13\), and \(6\times 6\) cells, which lights up 4–7 cells per bump.

6Why this representation is so good

  • Exponential capacity for free. If module \(i\) resolves \(k_i\) locations, the population resolves \(\prod_i k_i\). Ten modules of 25 locations each give \(25^{10}\approx 10^{14}\) codes — the paper's own example. Reading takes a fixed number of cells; capacity explodes with module count.
  • Uniqueness from ambiguity. Each module is deliberately ambiguous (it wraps). Disambiguation is an emergent property of reading several at once — no module needs to be big or precise.
  • Path integration is built in. Because phase updates linearly with movement (Eq. 4), the code at a location is the same no matter how you got there. Sensed landmarks "re-anchor" the bumps to cancel the drift that real path integration accumulates.
  • One map, reused everywhere. A module's manifold of phases is fixed. Entering a new object or environment just picks a new random starting bump (your 🎲 New seed), which instantiates a fresh, private location space — learned once, reused forever.
  • It's an SDR. Sparse, distributed, high-dimensional — so it inherits HTM's robustness: huge union capacity and a vanishingly small chance of false matches.

7Things to try

  1. See the aliasing. In the "Where else…" map, untick modules 2 and 3 so only module 1 contributes. The matching spots form a lattice — module 1 genuinely cannot tell those places apart. Re-tick the others and watch them collapse to one.
  2. Feel the scale. Drag module 1's scale up and down. Its arena lattice spreads or tightens, and its bump moves slower or faster for the same step — a coarse vs. fine ruler.
  3. Path independence. Note the final SDR, take a long detour with the arrows, then return to the same spot. Identical code. (The recenter button and a fixed seed make this exact.)
  4. Crank the resolution. Lower a module's \(\delta\varphi\): fewer cells fire (sparser), and its "distinguishable phases" count climbs — at the cost of needing finer movement to stay anchored.
  5. New environment. Hit 🎲. The sensor hasn't moved, but every module re-anchors to a random bump, so the whole location code changes — a different, private map for a different place.
